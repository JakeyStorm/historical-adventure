# A Historical adventure

Учебный проект «Шаг в будущее»: исторические видеорассказы, генерация новых сцен, русский диктор, источники и вопросы для самопроверки.

**Сайт:** https://historical-adventure.95-163-220-202.sslip.io/

## Возможности

- Просмотр четырёх подготовленных историй: Бородино, Колизей, полёт Гагарина и печатная мастерская Москвы 1564 года.
- Создание видео по описанию и, при необходимости, опорному изображению.
- Автоматический сценарий через Polza → `openai/gpt-4o-mini`.
- Видеосцены через `kling/v3`, отдельный русский голос через `openai/tts-1-hd`.
- Выбор голоса диктора: Onyx, Nova, Shimmer, Echo, Fable или Alloy.
- Кнопка «Послушать голос»: одна короткая русская фраза для сравнения всех шести голосов. Образцы созданы через ту же модель `openai/tts-1-hd` и хранятся в `dist/assets/voices/`; прослушивание не вызывает платный API.
- Монтаж видео, диктора и фоновых звуков через FFmpeg.
- Автоматическая публикация готового ролика и обложки в библиотеке.
- Текст рассказа, справочные ссылки, вопросы и явно обозначенная вымышленная модель «что если».

Посетитель вводит тему, выбирает настройки и нажимает **«Создать видео»**. Коды, ключи API и финансовые настройки ему не нужны. Обработка продолжается на сервере после закрытия вкладки.

## Как работает генерация

1. Сервер проверяет запрос, доступность провайдера и фактический баланс Polza.
2. Находит краткие справочные материалы через API русской Википедии. Если поиск недоступен, сообщает об этом в материалах ролика.
3. Текстовая модель пишет структурированный сценарий: кадры, подписи, рассказ и вопросы.
4. Сервер проверяет сценарий и заказывает до четырёх независимых видеосцен одновременно. Ролики длиннее 15 секунд состоят из нескольких фрагментов; при монтаже сохраняется их исходный порядок.
5. При включённом дикторе отдельно создаёт русскую аудиодорожку.
6. FFmpeg соединяет сцены, нормализует голос, приглушает фон и делает обложку.
7. Сервер проверяет длительность и наличие звука, затем сохраняет результат в библиотеке.

Если заказанный голос не получен, немой ролик не публикуется как готовый озвученный результат. Потерянный ответ платного API не вызывает автоматический повтор запроса.

При явном отказе провайдера 429 до принятия задания сервер снижает число одновременно создаваемых сцен. При неоднозначном ответе платный запрос не повторяется. Уже принятые задания сохраняются и их результаты забираются даже после ошибки следующей отправки. Записи общего журнала сериализованы, чтобы параллельные сцены не перезаписывали ID друг друга.

Сценарии и изображения — художественная ИИ-реконструкция. Найденные ссылки не заменяют проверку исторических сведений человеком.

## Запуск локально

Нужны **Node.js 24+** и **FFmpeg с ffprobe**. У проекта нет внешних npm-зависимостей.

```sh
cp .env.example .env
# Заполните POLZA_API_KEY и GENERATION_PASSWORD в .env
npm start
```

В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env`.

Откройте http://127.0.0.1:4173/. Для просмотра подготовленных историй ключ не нужен. Новая генерация требует работающего платного Polza API.

## Развёртывание на VPS

На действующем сайте используются Ubuntu 24.04, Docker Compose, Caddy и постоянный Docker-том с результатами. Видеокарта на VPS не нужна: нейросети работают у провайдера.

```sh
cp .env.example .env
# Заполните ключ и служебный пароль, задайте SITE_ADDRESS
docker compose up -d --build
docker compose ps
```

Для собственного домена направьте A-запись на IP VPS, укажите имя в `SITE_ADDRESS` и оставьте `CADDY_CONFIG=Caddyfile`. Для начального HTTP-просмотра используется `SITE_ADDRESS=:80`.

`Caddyfile.ip` — конфигурация HTTPS для текущего сервера и бесплатного технического адреса. При переносе замените существующий адрес на свой. На текущем VPS REG.RU сетевой MTU — 1450; Docker должен использовать совместимый MTU.

Приложение публикуется только через Caddy; порт 3000 остаётся внутри Docker. `TRUST_PROXY=true` допускается при такой схеме: Caddy формирует заголовки реального IP, которые используются для ограничения частоты запросов.

### Настройки

| Переменная | Назначение |
| --- | --- |
| `POLZA_API_KEY` | Ключ Polza, хранится только на сервере |
| `GENERATION_PASSWORD` | Служебный секрет для административного API, посетителю не показывается |
| `PUBLIC_GENERATION=true` | Генерация без пользовательского кода и регистрации |
| `POLZA_BUDGET_RUB=unlimited` | Дополнительный общий денежный лимит сайта отключён |
| `PUBLIC_MAX_JOB_RUB=unlimited` | Дополнительный лимит стоимости одного ролика отключён |
| `PUBLIC_JOBS_PER_HOUR=2` | До двух принятых заданий в час с одного IP |
| `POLZA_VIDEO_CONCURRENCY=4` | До четырёх одновременно создаваемых сцен; допустимо 1–4 |
| `POLZA_MAX_PRICE_PER_SECOND=10` | Ограничение тарифа провайдера Kling без фонового звука, ₽/с |
| `POLZA_MAX_AUDIO_PRICE_PER_SECOND=15` | Ограничение тарифа провайдера Kling с фоном, ₽/с |
| `TRUST_PROXY=true` | Доверять заголовкам установленного перед приложением Caddy |
| `DATA_DIR` | Папка состояния; в Docker `/app/data` |
| `FFMPEG_PATH` | Необязательный путь к FFmpeg |

Денежные лимиты сайта отключены по выбору владельца. Генерация использует реальный баланс Polza. Проверки баланса, ограничение частоты и защита от повторных списаний сохранены. При необходимости вместо `unlimited` можно указать числовой предел.

Не публикуйте `.env`, пароли сервера и содержимое `data/`. Для переноса сохраняйте Docker-том `video_data`. **`docker compose down -v` удаляет постоянные результаты.**

## Структура

```text
server.mjs          HTTP API, сессии посетителей, выдача видео
generation.mjs      очередь, журнал этапов, провайдер и защита от повторов
story.mjs           сценарий, поиск материалов, диктор, FFmpeg, библиотека
dist/               интерфейс, готовые истории и их медиа
tests/              проверки серверной логики и HTTP API
scripts/            бесплатная проверка Polza и упаковка исходников
Dockerfile          Node.js и FFmpeg
compose.yaml        приложение, Caddy и постоянные тома
.env.example        пример настроек без настоящих ключей
```

`data/jobs/` содержит журналы заданий, `data/generated/` — сцены, голос и готовые файлы, `data/library/` — опубликованные карточки. Анонимная HttpOnly-сессия связывает посетителя с его заданием; публичная библиотека доступна всем.

## Проверки

```sh
npm run check
npm test
npm run check:polza
```

Тесты используют подготовленные ответы внешних провайдеров и не расходуют баланс. Проверены сценарий, порядок этапов, HTTP-доступ, сессии, публикация, перезапуск, выбор голоса, параллельная обработка четырёх сцен, сохранение их порядка и ID, отсутствие повторных списаний, обработка явного отказа 429 и режим без денежных лимитов.

На VPS отдельно проверена настоящая сборка тестовых роликов через FFmpeg. Кроме того, посетитель самостоятельно создал через опубликованный сайт ролик о первом спутнике на 60 секунд: сценарий, четыре сцены, голос, монтаж и публикация прошли автоматически. По журналу этот запуск занял 17 минут 16 секунд; сцены создавались последовательно и заняли около 16 минут 28 секунд, монтаж — 32 секунды, диктор — 4 секунды. Это измерение прежней версии. Новый параллельный запуск через реальный платный API ещё не проверен; итоговое время зависит от очереди провайдера.

Ранее опубликованный ролик «Москва, 1564» создавался с ручным участием помощника; он не является доказательством полной автоматизации новой цепочки. Три исходных учебных рассказа также подготовлены заранее.

## Материалы

Источники приведены во вкладке каждого рассказа и в `dist/events.json`. Иллюстрация Бородина — картина Луи-Франсуа Лежена, архивное изображение Гагарина — NASA; основная художественная иллюстрация взята из материалов проекта. Сторонние изображения и медиа сохраняют условия своих источников.
